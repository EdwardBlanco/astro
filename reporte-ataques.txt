Formato para cada ataque:

ATAQUE #__ : (nombre)
Petición: MÉTODO /ruta
Body: { ... }
Respondió: código HTTP + lo que devolvió
Veredicto: DEFENDIDO / VULNERABLE
Qué noté: (qué esperabas que pasara vs qué pasó)

ATAQUE #1 : POST con campos obligatorios faltantes
Petición: POST /api/v1/auth/register
Body:
{
  "email": "prueba@test.com"
}
Respondió: 400 Bad Request
Respuesta del servidor:
{
	"mensaje": "Error de validación",
	"errores": [
		{
			"campo": "nombre_completo",
			"mensaje": "El nombre completo es obligatorio"
		},
		{
			"campo": "password_hash",
			"mensaje": "La contraseña es obligatoria"
		},
		{
			"campo": "fecha_nacimiento",
			"mensaje": "La fecha de nacimiento es obligatoria"
		}
	]
}
Veredicto: DEFENDIDO

ATAQUE #3 : Tipos de datos alterados
Petición: POST /api/v1/auth/register
Body:
{
  "nombre_completo": 12345,
  "email": 333,
  "password_hash": 232342342,
  "fecha_nacimiento": true
}
Respondió: 400 Bad Request
Respuesta del servidor:
{
	"mensaje": "Error de validación",
	"errores": [
		{
			"campo": "email",
			"mensaje": "Debe proporcionar un email válido"
		},
		{
			"campo": "fecha_nacimiento",
			"mensaje": "La fecha debe tener formato válido (YYYY-MM-DD)"
		}
	]
}
Veredicto: VULNERABLE
Qué noté: La API no validó el número en los campos nombre_completo y password_hash. La API aceptó un tipo numérico.
